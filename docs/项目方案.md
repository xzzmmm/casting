# CastingNuwa・选角女娲 — 项目方案

> 基于 "思维蒸馏" 理念的 AI 戏剧选角辅助系统
> 灵感来源：GitHub 开源项目 nuwa-skill（女娲.skill）



***

## 一、项目背景

### 1.1 真实痛点

莱恩戏剧社（Lion Drama Club, Diligentia College）在课程分享中明确指出了剧团运营中的多个实际难题。其中，**演员选角（Casting）** 是一个被低估但影响深远的环节：



* **演员经验匮乏**："大部分人都是第一次接触戏剧，大家并不知道如何饰演一个角色"—— 学生剧团中绝大多数演员没有表演经验，导演难以判断其潜力

* **导演认知有限**：导演不可能深入了解每一位报名演员的特质，选角往往依赖第一印象或短暂试镜

* **选角全凭感觉**：缺乏系统化的评估框架，选角决策不可解释、不可复现

* **错配成本高昂**：角色与演员不匹配会导致排练效率低下、演员信心受挫、最终演出质量下降

### 1.2 选角的杠杆效应

选角是演员训练的前置环节。选对了角色：



* 演员更容易进入角色，降低训练成本

* 排练效率提升，减少导演的指导负担

* 最终演出质量更有保障

选错了角色，则后续所有环节都在弥补前期的决策失误。

### 1.3 现有方案的局限



* **传统选角**：依赖导演个人经验和直觉，不可量化、不可解释

* **AI 角色扮演工具**：仅模仿语气和用词，不涉及角色深层认知结构

* **通用 LLM 对话**：没有针对戏剧选角的结构化分析，输出零散不可用

## 二、项目目标

### 2.1 核心理念

将 nuwa-skill 的**思维蒸馏（Cognitive Distillation）** 理念从 "蒸馏名人的思维方式" 迁移到 "蒸馏戏剧角色的认知操作系统"：

> 女娲用泥土造人；CastingNuwa 用剧本造角色卡。

nuwa-skill 蒸馏的是一个真实人物的心智模型、决策启发式、表达 DNA；CastingNuwa 蒸馏的是一个虚构角色的性格特质、核心动机、行为模式、语言 DNA、情感弧线 —— 生成结构化的 "角色卡"，再与演员的多模态画像做智能匹配。

### 2.2 分阶段目标



| 阶段          | 目标            | 交付物                | 时间        |
| ----------- | ------------- | ------------------ | --------- |
| **Phase 1** | 角色蒸馏模块        | 剧本→结构化角色卡（CLI 原型）  | 第 1-3 周   |
| **Phase 2** | 演员画像模块        | 试镜视频 / 音频→演员多维度画像  | 第 4-6 周   |
| **Phase 3** | 匹配引擎 + Web 界面 | 角色 × 演员匹配矩阵 + 选角报告 | 第 7-10 周  |
| **Phase 4** | 真实场景验证与迭代     | 用莱恩戏剧社真实数据测试优化     | 第 11-14 周 |

### 2.3 本期交付范围（Phase 1 原型）



* 完整的角色蒸馏模块代码

* 可运行的 CLI 工具

* 示例剧本与示例输出

* 项目方案文档（本文档）

## 三、核心概念

### 3.1 思维蒸馏（Cognitive Distillation）

nuwa-skill 的核心创新：不是让 AI 模仿某个人说话（角色扮演），而是从公开信息中提炼这个人的**认知操作系统**—— 心智模型、决策启发式、表达 DNA、反模式、诚实边界 —— 生成可运行的 Skill，让 AI 用这个人的思维方式分析问题。

其技术实现为 4-Agent 并行蒸馏流水线：



1. **语言学分析器**（Linguistic Profiler）：语气、口头禅、词汇、表达风格

2. **认知心理学家**（Cognitive Psychologist）：思维模型、决策启发、价值观、反模式

3. **角色工程师**（Roleplay Engineer）：身份卡 + 三步工作流

4. **主合成器**（Master Synthesizer）：合成结构化 JSON → Skill.md

### 3.2 角色蒸馏（Role Distillation）

CastingNuwa 将蒸馏对象从 "真实人物" 迁移到 "戏剧角色"。戏剧角色同样拥有一套完整的 "认知操作系统"：



| 蒸馏维度 | 真实人物（nuwa-skill） | 戏剧角色（CastingNuwa） |
| ---- | ---------------- | ----------------- |
| 身份   | 姓名、职业、背景         | 角色名、剧中身份、背景设定     |
| 认知   | 心智模型、决策启发式       | 性格特质、核心动机、行为模式    |
| 表达   | 语气、口头禅、词汇偏好      | 语言 DNA、句式特点、说话方式  |
| 边界   | 反模式、诚实边界         | 角色局限性、不可逾越的设定     |
| 关系   | 社会关系网络           | 剧中人物关系图谱          |
| 演进   | —                | 情感弧线（从开场到结尾的变化）   |
| 选角   | —                | 选角指引（适合什么样的演员）    |

### 3.3 与传统选角的本质区别



* **传统选角**：导演看试镜 → 凭感觉判断 → 不可解释

* **CastingNuwa**：AI 蒸馏角色认知 → AI 分析演员特质 → 结构化匹配 → 给出可解释的匹配理由和风险提示

AI 不是替代导演做决策，而是为导演提供**系统化的决策支持**—— 就像导航软件不替代司机开车，但提供路线规划和实时路况。

### 4.2 四 Agent 蒸馏流水线（对标 nuwa-skill）



| Agent                        | 职责                 | 输入             | 输出                  |
| ---------------------------- | ------------------ | -------------- | ------------------- |
| **角色蒸馏器**（Role Distiller）    | 从剧本中提取角色的认知操作系统    | 剧本文本           | 角色卡（结构化 JSON）       |

## 五、模块详细设计

### 5.1 角色蒸馏模块（Phase 1 核心交付）

#### 5.1.1 输入输出



* **输入**：剧本文本（.txt/.docx/ 直接粘贴）

* **输出**：角色卡列表（JSON 格式），每个角色包含 7 个分析维度

#### 5.1.2 角色卡七大维度

**维度 1：基本信息（Profile）**



* 角色名、剧中身份、年龄 / 性别（如剧本有提及）

* 出场场景统计、台词数量

**维度 2：性格特质（Personality）**



* 3-5 个核心性格特质

* 每个特质附剧本中的具体证据（台词 / 行为 / 场景描述）

* 特质之间的关系（如 "外表冷漠但内心敏感"）

**维度 3：核心动机（Motivation）**



* 角色最根本的欲望（Want）

* 角色最深层的需求（Need，往往与 Want 形成张力）

* 角色的恐惧（Fear）

* 动机在剧情中的变化轨迹

**维度 4：行为模式（Behavioral Patterns）**



* 角色在压力下的典型反应

* 角色在冲突中的行为倾向（对抗 / 逃避 / 妥协 / 操纵）

* 角色的习惯性动作或行为特征

* 角色的决策模式（冲动 / 谨慎 / 理性 / 感性）

**维度 5：语言 DNA（Linguistic DNA）**



* 用词偏好（正式 / 口语 / 文雅 / 粗粝）

* 句式特点（简短有力 / 冗长复杂 / 反问 / 陈述）

* 口头禅或标志性表达

* 语气特征（嘲讽 / 温柔 / 坚定 / 犹豫）

* 语言中的身份标记（教育背景 / 地域 / 时代）

**维度 6：情感弧线（Emotional Arc）**



* 开场时的情感状态

* 关键转折点的情感变化

* 结尾时的情感状态

* 整体弧线类型（成长 / 堕落 / 救赎 / 幻灭 / 循环）

* 情感变化的关键触发事件

**维度 7：选角指引（Casting Guide）**



* 适合该角色的演员类型（声线特质、气质类型、外形倾向）

* 该角色对演员的核心能力要求（如 "需要爆发力"" 需要内敛的情感表达 "）

* 试镜时建议考察的重点场景或台词

* 选角风险提示（如 "该角色容易被演成脸谱化，需要演员有层次感"）

* 与其他角色的化学反应要求（如 "与角色 X 需要有强烈的张力"）

#### 5.1.4 Prompt 设计策略

角色蒸馏采用**结构化引导 + 证据约束**的 Prompt 设计：



1. **系统提示**：定义角色分析师身份，明确 7 个分析维度和输出格式

2. **证据约束**：要求每个分析结论必须附剧本原文证据，避免凭空编造

3. **选角导向**：特别强调第 7 维度（选角指引），确保输出直接服务于选角决策

4. **JSON 强制输出**：要求严格的 JSON 格式，便于后续程序处理

### 5.2 演员画像模块（Phase 2 规划）

#### 5.2.1 多模态输入



* **视频**：试镜录像 → 面部表情分析（表情幅度、微表情、眼神）+ 肢体语言分析（手势、姿态、移动方式）

* **音频**：试镜录音 → 声线分析（音高、音色、语速、节奏）+ 情感表达分析（情感范围、情感转换能力）

* **文本**：自我介绍 + 过往表演经历 → 背景分析、表演经验、自我认知

#### 5.2.2 演员画像维度



| 维度         | 子维度                            | 数据来源      |
| ---------- | ------------------------------ | --------- |
| **声线特质**   | 音高、音色、清晰度、语速、节奏、共鸣             | 音频        |
| **面部表现力**  | 表情幅度、微表情控制、眼神传达、面部对称性          | 视频        |
| **肢体表现力**  | 手势丰富度、姿态自然度、空间使用、移动流畅度         | 视频        |
| **情感表达范围** | 能表达的情感种类、情感深度、情感转换流畅度          | 音频 + 视频   |
| **气质类型**   | 整体气质印象（如 "沉稳"" 灵动 ""阴郁"" 阳光 "） | 多模态综合     |
| **表演风格**   | 表现派 / 体验派倾向、自然度、节奏感            | 多模态综合     |
| **经验与潜力**  | 表演经验、学习能力、可塑性                  | 文本 + 试镜表现 |

### 5.3 匹配引擎（Phase 3 规划）

#### 5.3.1 匹配逻辑

匹配引擎采用**双轨匹配**：

**轨道 1：硬性匹配（Hard Match）**



* 角色的硬性要求（性别、年龄范围、特殊技能如唱歌 / 跳舞 / 武术）

* 演员是否满足 → 不满足直接排除

**轨道 2：软性匹配（Soft Match）**



* 角色卡的 7 个维度与演员画像的 7 个维度做语义匹配

* 使用嵌入向量计算相似度 + LLM 推理给出匹配理由

* 输出 0-100 分的匹配度评分

#### 5.3.2 匹配输出

对每个 "角色 × 演员" 组合，输出：



* 匹配度总分（0-100）

* 分维度匹配评分（性格 / 动机 / 语言 / 情感 / 气质等）

* 匹配理由（为什么适合）

* 风险提示（可能的问题）

* 试镜建议（如果进入下一轮，应该考察什么）

### 5.4 Web 界面（Phase 3 规划）

#### 5.4.1 核心页面



1. **剧本导入页**：上传剧本 → 自动生成角色卡列表

2. **角色卡详情页**：展示单个角色的 7 维度分析，可编辑

3. **演员上传页**：演员上传试镜视频 / 音频 / 自我介绍

4. **演员画像页**：展示单个演员的多维度画像

5. **匹配矩阵页**：角色 × 演员的匹配度热力图，点击查看详情

6. **选角报告页**：汇总所有匹配结果，可导出 Excel/PDF

#### 5.4.2 交互设计原则



* 导演视角：快速浏览、一键匹配、重点突出

* 可解释性：每个评分都有理由，不是黑盒

* 可干预性：导演可以手动调整角色卡或演员画像，重新匹配

* 导出友好：选角报告可直接用于剧组沟通

## 八、风险与应对



| 风险             | 影响           | 概率 | 应对策略                                                          |
| -------------- | ------------ | -- | ------------------------------------------------------------- |
| **LLM 输出不稳定**  | 角色卡格式错误、内容编造 | 中  | 严格 JSON 输出约束 + 输出校验 + 证据要求（每个结论附剧本原文）                         |
| **真实试镜数据获取困难** | 无法在真实场景验证    | 中  | 提前与莱恩戏剧社沟通；用公开影视片段做替代测试；用合成数据做单元测试                            |
| **多模态分析精度不足**  | 演员画像不准确      | 中高 | Phase 2 先用语音分析（较成熟），CV 部分用开源模型做基础版，不追求高精度；匹配时 LLM 推理可弥补部分精度不足 |
| **匹配算法可解释性差**  | 导演不信任 AI 建议  | 低  | 匹配引擎设计为 "评分 + 理由 + 风险" 三段式，每个结论都有自然语言解释；允许导演手动调整              |
| **项目范围过大**     | 无法在学期内完成     | 中  | 严格分阶段交付，Phase 1 为最小可行产品（MVP），即使后续阶段未完成也有可展示的成果                |
| **API 成本**     | LLM 调用费用     | 低  | 使用性价比高的开源 / 国产模型；角色蒸馏为一次性操作（蒸馏后角色卡可复用）；提供本地模型替代方案             |

## 十、创新点总结



1. **概念迁移创新**：将 nuwa-skill 的 "思维蒸馏" 从真实人物迁移到戏剧角色，提出 "角色蒸馏" 概念 ——*"女娲造人，我们造角色卡"*

2. **认知级角色分析**：不同于传统的角色简介（年龄、身份、性格标签），CastingNuwa 蒸馏的是角色的 "认知操作系统"—— 动机、决策模式、行为倾向、语言 DNA、情感弧线，达到选角所需的深度

3. **可解释的 AI 选角**：匹配引擎输出的不是黑盒分数，而是 "匹配理由 + 风险提示 + 试镜建议"，让 AI 成为导演的决策助手而非替代者

4. **多模态演员画像**：结合 CV（面部 / 肢体）、语音（声线 / 情感）、文本（背景 / 经验）三种模态，构建比传统试镜记录更全面的演员画像

5. **学生剧团适配**：针对 "演员无经验、导演不了解演员、选角全凭感觉" 的学生剧团痛点设计，而非面向专业选角团队的复杂工具

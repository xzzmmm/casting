# CastingNuwa · 选角女娲 — 提示词体系总览（v0.5）

> 本文件夹整理 CastingNuwa 项目中所有 LLM 提示词（Prompt），方便查看、调试和复用。
> 设计灵感对标 GitHub nuwa-skill（女娲思维蒸馏）：从文本中蒸馏结构化认知模型，每个结论必须附原文证据。

## v0.5 的根本转变

项目从「上传材料 → AI 打分排名」，改为「**引导学生剧团完成一轮有依据、可复核的选角**」。
AI 不再扮演"演技评委"下结论，而是"选角观察助手"，帮导演整理观察、准备下一轮验证。

三条不可混淆的概念：

| 概念 | 回答的问题 | 说明 |
|------|-----------|------|
| 特征强度 | 表演是否外放、情绪波动是否强烈？ | 是**风格**，不是好坏 |
| 表演质量 | 表达是否准确、有层次、服务情境？ | 需导演判断，AI 只提供线索 |
| 角色匹配 | 这种表现是否适合当前角色和导演意图？ | 性格相似 ≠ 适合出演 |

> 一个"情感张力=3"的克制角色可能需要极高演技；哭得激烈也可能缺乏情境依据。

## 提示词模块

| 编号 | 模块 | 文件 | 用途 |
|------|------|------|------|
| 01 | 角色蒸馏 | `01_role_distillation.md` | 剧本 → 角色卡，重点是把性格标签转成**可观察表演要求** |
| 02 | 演员观察 | `02_actor_profiling.md` | 试镜材料（文本/音频/视频）→ **观察记录 + 待验证项**（不再是演技打分） |
| 03 | 制作团队分析 | `03_crew_analysis.md` | 剧本 → 后台岗位需求清单（灯光/音效/舞美/服装/道具/化妆），v0.5 未改动 |

## 核心设计原则

1. **可观察而非贴标签**："角色内向"要转化为"通过停顿、回避目光和有限动作，让观众理解角色不愿表露的情绪"。
2. **观察记录四要素**：发生了什么（带时间戳）→ 可能意味着什么（保留其他解释）→ 依据是否充分（直接观察/推断/无法判断）→ 下一轮怎么验证。
3. **证据分离**：实际表演证据、演员自述、过往经历分开存储；"说自己擅长"不等于"已展示能力"。
4. **材料不足给待验证项，不硬给中等分**：有效证据少于 2 条时，量化分设为 `null`、置信度"无法判断"。
5. **指导后复试**：第一遍自然表演后给明确调整指令，第二遍观察变化，区分"碰巧合适"与"能执行指导"。
6. **纯 JSON 输出**：所有提示词输出严格 JSON，便于程序解析与证据比对。

## 量化分的定位

5 个维度（外向性/情感张力/理性度/强势度/可信度）的 0-10 分**只描述"角色或表演的特征强度"，不是演技评分**。
在候选方案中，数值相似度仅作为折叠展示的"参考分"，结论以可观察要求的证据逐条对照为准。

## 使用方式

- **代码中使用**：提示词封装在 `src/prompts.py`、`src/actor_prompts.py`、`src/crew_prompts.py`。
- **手动调试**：复制对应文档的 System Prompt + User Prompt，填入材料到任意 LLM 即可测试。
- **演示模式**：未配置 `LLM_API_KEY` 时使用内置示例数据，所有结果会显式标注 `analysis_status="demo"`，不能作为选角依据。

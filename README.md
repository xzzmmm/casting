# CastingNuwa・选角女娲

> 引导学生剧团完成一轮**有依据、可执行、可复核**选角的 AI 助手
> 灵感来源：[nuwa-skill](https://github.com/alchaincyf/nuwa-skill)（女娲.skill）

***

## 这个项目解决什么问题

**女娲造人，我们造角色卡。**

学生剧团选角常依赖导演个人的经验与直觉：剧本里的角色描述、舞台指示与实际人员配置之间存在信息断层，导致选角周期长、试镜初筛效率低、后台人员配置靠拍脑袋，事后也很难复核"当时为什么选了这个人"。

nuwa-skill 蒸馏的是真实人物的思维方式，CastingNuwa 把这套理念迁移到戏剧领域，但 v0.6 起定位做了关键调整：

> **AI 不替导演打分、不下"谁演技好"的结论，而是引导剧团走完选角流程，并把每一步的依据整理清楚。**

三条不能混淆的界线：

| 概念 | 实际在问什么 |
| --- | --- |
| 特征强度 | 表演是否外放、情绪波动是否强烈 |
| 表演质量 | 表达是否准确、有层次、服务于情境 |
| 角色匹配 | 这种表现是否适合当前角色与导演意图 |

"情感张力 5 分"只代表表达强度适中，不代表演技只有 5 分。克制的表演可能非常出色，哭得激烈也可能缺乏情境依据。因此系统输出**观察记录与候选方案**，把最终判断权留给导演。

## 六步引导式流程

Web 界面按以下顺序组织，前一步未完成时会主动拦截或提示：

1. **角色蒸馏**：输入剧本，生成角色卡，并把"内向""强势"这类性格标签翻译成**可观察的表演要求**（例如"通过停顿、回避目光和有限动作，让观众理解角色不愿表露的情绪"）。
2. **选角设定**：登记剧团的表演风格、导演阐述、哪些要求**必须满足**、哪些**可以靠排练改善**、是否接受反串/兼角、档期约束。负责人确认后才能进入匹配。
3. **试镜任务**：为每个角色生成统一试镜材料、2 到 3 个观察重点（含正面/负面信号）、一条明确的调整指令和一段复试任务，可导出为文本。
4. **演员观察**：记录试镜表现，输出"发生了什么 → 可能意味着什么（保留其他解释）→ 依据类型 → 下一轮怎么验证"。支持**指导后复试**（第一遍自然演，给指令后第二遍复试，区分"碰巧合适"和"能执行指导"）。材料不足时生成**待验证项**，不硬给中等分。
5. **候选与确认**：按角色的可观察要求逐条核对证据，把演员分为"优先试演 / 需要补充试镜 / 存在明确限制"，并做兼角、档期、对手戏化学反应检查。负责人**人工确认最终人选并保存理由**，形成最终选角决定表。
6. **制作团队分析**：从剧本推导灯光、音效、舞美、服装、道具、化妆等后台岗位需求，每条结论附剧本依据。

### 三种演员输入模式

- 📝 **文本模式**：自我介绍加试镜转写，支持两轮复试与档期记录，多位演员用单独一行 `---` 分隔。
- 🎵 **音频模式（双模态）**：faster-whisper 转写加 librosa 声学特征，再加语言模型融合。
- 🎥 **视频模式（三模态）**：音频分析加视觉抽帧分析。视频按**全片均匀采样**并保留每帧时间戳，避免只看到开头；声音或动作变化只作为观察线索，不直接等同于"演得好"。

## 工程与数据原则

- **会话隔离**：每个浏览器会话拥有独立状态，多人同时使用不串数据。
- **项目存档**：可把整个项目（剧本、角色卡、设定、试镜任务、观察记录、候选方案、确认结果）保存为 JSON，并随时重新加载继续。
- **改动可追溯**：剧本重新蒸馏后，下游的设定、试镜、观察、候选会被重置并提示重跑，避免用过时结论。
- **失败不造假**：配置了 API Key 但真实调用失败时会**明确报错**，不会静默回退演示数据；只有在完全没有配置 Key 时才进入演示模式，且页面全程标注 demo。
- **证据强约束**：任一特征维度有效证据少于 2 条时，分值强制为空、置信度为"无法判断"。
- **证据分来源**：演员自述、过往经历、实际表演证据分开存放，"说自己擅长"不等于"已经展示了能力"。

## 快速开始

### 1. 安装依赖

```
pip install -r requirements.txt
pip install -r requirements_web.txt
```

核心依赖：`openai`（LLM 调用）、`gradio`（Web 界面）；多模态还需要 `faster-whisper`、`librosa`、`moviepy`、`opencv-python`、`mediapipe`。

### 2. 配置 LLM API（可选）

复制 `.env.example` 为 `.env`，填入 API 信息。支持所有 OpenAI 兼容接口：DeepSeek、智谱 GLM、豆包、通义千问、OpenAI 等。

不配置 API 也能运行，程序进入**演示模式**并在页面明确标注，输出为示例数据，不能作为真实选角依据。

### 3. 启动 Web 界面

```
python app.py
```

浏览器自动打开 `http://127.0.0.1:7860`，按 ① 到 ⑥ 的标签页顺序操作，顶部可随时保存或加载项目 JSON。

### 4. 命令行使用

```
# 角色蒸馏（全角色）
python main.py --script examples/sample_script.txt --summary

# 单角色深度
python main.py --script examples/sample_script.txt --role "莱恩" --summary
```

## 技术栈

- **LLM 推理**：OpenAI 兼容 API，结构化 JSON 输出与证据约束
- **Web 界面**：Gradio，会话级状态隔离
- **语音**：faster-whisper 转写、librosa 声学特征
- **视觉**：OpenCV 全片均匀抽帧；MediaPipe 面部/姿态（在不支持的 Python 版本上自动降级为纯抽帧并标注）
- **数据模型**：Python dataclass，全部支持序列化与项目存档往返

## 常见问题

### Q: 没有 API Key 能用吗？

A: 可以，会进入演示模式体验完整流程，但所有结果都标注为 demo，不能用于真实选角。配置 Key 后若调用失败会明确报错，而不是偷偷用假数据。

### Q: 系统会给演员的演技打分排名吗？

A: 不会直接给"演技好坏"结论。它整理可观察的表现、证据覆盖和待验证项，把演员分为优先试演、需要补充试镜、存在明确限制三类，最终人选由导演确认并写明理由。

### Q: 换一个剧本还能用吗？

A: 可以。角色卡、试镜任务、团队需求都从当前剧本实时生成；更换剧本重新蒸馏后，系统会提示下游内容需要重算。

### Q: 视频分析为什么有时没有面部数据？

A: 在部分 Python 版本上 MediaPipe 不可用，系统会降级为全片抽帧并明确标注，时间戳仍然保留，供逐段核对，不会用空结果冒充成功。

SerialDoc 剧集剧本诊断助手

电视剧与舞台剧是两种不同的结构生物：几十集、随时可弃、靠钩子留人、多条线并行、跨集埋雷。SerialDoc 把「注水、弃剧、断线、忘伏笔」这些剧集行业的老大难，变成可定位、可量化、可修改的集级与季级诊断报告。
姊妹项目：ScriptDoc（舞台剧版） 项目周期：6 周 · 4 个里程碑 文档日期：2026-09-07 交付形态：Web 应用
01

项目概述

OVERVIEW

舞台剧观众买了票会看完；电视剧观众一个不喜欢的开头就能弃剧。所以剧集剧本诊断的核心不是「哪里不好」，而是「观众会在哪里走、为什么走、怎么留」。SerialDoc 在 ScriptDoc 的混合架构（规则 + 统计 + LLM 结构化判断）之上，增加剧集独有的四类检测：分层节奏、集末钩子与弃剧点、注水检测、跨集连续性，并升级双线为多线并行结构分析。

一句话定位
面向剧集编剧与制片团队的剧本诊断工具：分层节奏 + 弃剧点 + 注水 + 跨集伏笔追踪
目标用户
剧集编剧（长线结构把关）、剧本医生（story doctor）、制片（过稿前预审）
核心场景
全季导入 → 季总览热力图 → 弃剧风险预警 → 单集/跨集下钻 → 伏笔回收表
技术亮点
注水密度、钩子强度、伏笔状态机均为可复算规则；LLM 只做语义判断；可接真实追剧数据验证
02

问题定义

PROBLEM DEFINITION

2.1 舞台剧 vs 电视剧：结构性差异决定检测维度

维度舞台剧（ScriptDoc）电视剧（SerialDoc）
观看场景单场 2 小时，观众基本看完几十集 × 随时可弃，每集末尾决定是否追下一集
节奏层级单层：全剧一条张力曲线分层：季节奏 / 集节奏 / 场景节奏，三层都要看
悬念机制幕间留扣子即可集末钩子（cliffhanger）是留人核心，缺失=流失
结构三幕式每集小结构 + 全季大结构 + 类型公式（单元剧/连续剧）
并行线通常双线3~5 条线并行（主线/副线/单元线），切场与遗忘是高频病
状态一致性单场，跨场矛盾少见跨集状态：伏笔回收、人物伤病情、时间线，隔 10 集就忘
数据量单剧本 2~4 万字全季 40~120 万字 → 批处理流水线，按集/场分片

2.2 痛点拆解：六类「剧集病」→ 可检测信号

原则：每一种「感觉不对」，都必须映射为至少一种可复现的检测方法，否则不进入产品范围。

痛点症状（主观感受）检测信号（客观可复算）
注水「这集没讲啥」「倍速看」「可跳过」情节密度 = 信息事件数 / 有效时长；无信息对话占比；重复闪回率；可删场景
弃剧「前三集留不住人」「开头平淡」第 1-3 集钩子强度曲线；开场前 5 分钟信息量；每集末悬念强度
断线「那条副线呢？」「这条线跟主线啥关系」多线识别（角色-场景聚类）；线被遗忘段（单线连续 >N 场）；线间关联度
忘伏笔「那个钥匙呢？」「前面埋的坑没填」伏笔状态机：埋设 → 待回收 → 回收/失效，跨集追踪未回收项
穿帮「上集受伤下集好了」「时间对不上」人物状态表跨集校验；时间线冲突检测（事件顺序/时长）
人物弧光断裂「人设崩了」「第十集换人了」长线风格漂移检测（复用人物档案，扩展到全集范围）
03

技术架构

ARCHITECTURE

五层架构，与 ScriptDoc 同源，差异集中在数据层的「跨集索引库」与分析层的「集/季两级聚合」——这是电视剧「跨集」特性的根。

直接复用 ScriptDoc：中二度规则引擎（chuuni_engine，25 项测试通过）、幽默分析三维（幽默×冒犯×含蓄）、场景张力统计、人物档案。剧集版不重写台词层，只做规模适配与跨集扩展。

05

核心模块

MODULES
M1 · 集结构诊断
每集三幕结构完整度、开场钩子、集末悬念（cliffhanger）强度——「能不能留住人看下一集」
M2 · 弃剧点风险
第 1-3 集聚焦：前 5 分钟信息量、钩子密度曲线、弃剧风险分——「观众会不会点进来」
M3 · 多线并行
N 线识别（角色-场景聚类）、切换节奏、线被遗忘段、线间关联、结尾交汇
M4 · 注水检测
情节密度、无信息对话占比、重复闪回率、可删场景——「哪段可以倍速/跳过」
M5 · 跨集连续性
伏笔状态机（埋设→待回收→回收/失效）、人物状态表校验、时间线冲突——「坑填没填、穿没穿帮」
M6 · 角色弧光
长线成长曲线、风格漂移（跨全集）、口头禅漂移——「人设崩没崩」
M7 · 台词质量
中二度 / 幽默分析（幽默×冒犯×含蓄）/ 自然度——直接复用 ScriptDoc 引擎
M8 · 类型公式
单元剧 vs 连续剧模式识别；医疗/职场剧每集「病例+主角线」公式符合度
06

详细设计

DETAILED DESIGN

6.1 M2 弃剧点风险（剧集版最核心模块）

检测信号判据 / 阈值（设计值）实现方式
开场 5 分钟信息量第 1 集开场 5 分钟（约 8-10 场前）信息事件数 <3 → 「开局平淡」；<1 → 高弃剧风险规则（复用信息密度统计）
集末悬念强度每集末 3 场内无未解悬念 → 钩子缺失；悬念类型分：情节钩 / 情感钩 / 笑点钩LLM（悬念识别）+ 规则（位置判定）
第 1-3 集钩子曲线三集钩子强度单调不升 → 「前紧后松」流失风险；第 1 集钩子为全集最弱 → 高风险统计（三集钩子强度对比）
弃剧风险分风险分 = 加权（开场信息量 0.3 + 集末悬念 0.4 + 钩子曲线 0.3），0-100规则（可复算）

6.2 M4 注水检测（可复算的统计量）

检测信号判据 / 阈值（设计值）实现方式
情节密度密度 = 信息事件数 / 有效时长；低于全集密度 40% 分位的场景 → 疑似注水规则（事件抽取+统计）
无信息对话占比寒暄/重复/空转对话行占比 >35% → 注水预警规则 + LLM（复用空转判定）
重复闪回率同一回忆片段被复述 ≥3 次且无新信息 → 注水；闪回是否推进信息LLM（语义相似度判定）
可删场景删去后不影响主线/副线/人物关系的场景 → 「可删」标记（不自动删，只建议）LLM（因果影响判断）

6.3 M5 跨集连续性 · 伏笔状态机（答辩「规则可追踪」亮点）

伏笔生命周期

埋设（第 N 集出现未解释元素）→ 待回收（跨集仍无解释）→ 回收（后续集给出解释）／ 失效（明确废弃或烂尾）

跨集追踪：元素出现 → 记录唯一 ID → 每集扫描是否被解释/重提 → 全集结束时输出「未回收伏笔清单」，按埋设集排序，标出「已 10 集未回收」的雷。

检测信号判据 / 阈值（设计值）实现方式
伏笔识别与追踪埋设元素（道具/台词/人物秘密）→ 跨集状态机；全集未回收且埋设已过 1/2 全季 → 烂尾预警规则（状态机）+ LLM（识别）
人物状态一致性伤病情/关系状态/能力状态跨集冲突（如上集重伤下集完好）→ 穿帮规则（状态表比对）
时间线冲突事件顺序倒置、跨集时长不匹配（一天内完成三集旅程）→ 时间穿帮规则 + LLM（时序推理）

6.4 M3 多线并行（由双线升级为 N 线）

检测信号判据 / 阈值（设计值）实现方式
线识别角色—场景共现矩阵聚类 → 自动分出主线/副线/单元线（N 条）规则（聚类，可复算）
线被遗忘段任一条线连续缺席 ≥4 集 → 「副线失踪」预警统计
切换节奏平均每集切换次数 >6 且无悬念动机 → 切太碎；单线霸屏 ≥3 集 → 失衡统计 + LLM（动机判断）
结尾交汇季末各线是否收束；主线与 50%+ 副线未交汇 → 结构残缺LLM + 规则

6.5 输出形态

  • 季总览热力图：横轴集数 × 纵轴指标（张力/钩子/注水/笑点），一眼看全季健康度——答辩主视觉
  • 弃剧风险报告：第 1-3 集专项，含前 5 分钟分析与集末钩子清单
  • 伏笔回收表：埋设集 / 内容 / 回收集 / 状态，未回收项置顶标红
  • 多线泳道图：N 线沿全集时间轴展开，标注切换点与失踪段

09

验收指标

METRICS
指标目标值度量方式
注水场景检出召回率≥ 70%与编剧/制片人工标注的注水场景对比
伏笔回收追踪准确率≥ 80%状态机结果 vs 人工伏笔清单逐项核对
切换生硬点检出率≥ 75%与人工标注的多线切换点对比
弃剧风险分有效性AUC ≥ 0.7（目标）与真实追剧留存数据对比（若能获取；否则退化为编剧打分相关性）
建议采纳率≥ 50%编剧采纳 / 部分采纳建议条数占比

口径声明：以上为方案设定的验收目标值，非已实测数据；答辩前用真实剧本完成标注采集后替换。弃剧风险分的 AUC 目标依赖外部留存数据可得性，作为「若可获取」的加分项而非硬指标。

10

答辩亮点

HIGHLIGHTS
亮点论证对应用户/评委痛点
分层节奏是剧集独有季 / 集 / 场三层节奏各有一套检测，舞台剧方案只有一层——不是复制粘贴，是结构适配「这个方案跟舞台剧版有什么不同」
注水密度可复算情节密度 = 信息事件数 / 有效时长，纯统计量，任何人可复算「是不是套壳大模型」
伏笔状态机可追踪埋设 → 待回收 → 回收 / 失效，每条伏笔有唯一 ID 与状态流转，报告可逐条核对「检测结果凭什么信」
可接真实数据验证弃剧风险分可对接平台留存/弹幕数据做 AUC 验证——数据科学含量比纯文本分析更硬「有没有数据科学方法」
引擎复用率台词层（中二度/幽默）直接复用 ScriptDoc，架构上体现「一个平台、两种体裁」「工程量与深度」

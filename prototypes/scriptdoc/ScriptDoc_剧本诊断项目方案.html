ScriptDoc 剧本诊断助手

把「台词尴尬、情节不合逻辑、缺张力」这类主观感受，变成可定位、可量化、可修改的结构化诊断报告——让非专业编剧知道「哪里不对、为什么不对、怎么改」。
痛点来源：社团演讲 · 社团创作六大难题 项目周期：6 周 · 4 个里程碑 文档日期：2026-09-07 交付形态：Web 应用
01

项目概述

OVERVIEW

剧本是戏剧的根。但校园剧社的剧本修改长期依赖「读出来感觉不对」——没有人能指出具体是哪一句台词、哪一个转折、哪一条人物线出了问题。ScriptDoc 用「统计特征 + 规则引擎 + 大模型结构化分析」的混合架构，为每一部剧本生成四维诊断报告（结构 / 台词 / 人物 / 逻辑），每个问题都能定位到场景与行号，并给出可执行的修改建议。

一句话定位
面向校园戏剧社的智能剧本诊断 Web 工具：诊断为主、不改写、可定位、可量化
目标用户
编剧（初稿找问题）、导演（排练前过硬伤）、副导演 ASM（版本与反馈管理）
核心场景
初稿完成 → 排练前诊断 → 迭代修改 → 多版本对比，全程追踪「改没改好」
技术亮点
非「套壳 ChatGPT」：统计特征与规则引擎承担可复算部分，LLM 只做结构化判断，结果可追溯
02

问题定义

PROBLEM DEFINITION

2.1 痛点拆解：把主观感受转成可检测的信号

原则：每一种「感觉不对」，都必须映射为至少一种可复现的检测方法，否则不进入产品范围。

主观抱怨可检测的信号检测方法
台词尴尬口语化程度低、书面语过重；句长分布不自然；独白式对白（一人连续占多轮）；信息密度失衡语言统计特征（句长、口语标记词、轮次分布）+ LLM 自然度评分（锚定具体台词句）
情节不合逻辑因果链断裂；行为动机缺失；伏笔未回收；时间 / 空间矛盾情节因果链抽取 + 规则引擎伏笔—回收匹配 + LLM 一致性校验
缺张力冲突密度低；目标—障碍链薄弱；转折点稀疏；高潮前置或缺失场景张力曲线：按节拍标注「目标 / 障碍 / 转折 / 高潮」密度，输出曲线与拐点
人物不像同一角色的台词风格漂移；情绪反应前后矛盾；人物说话「一个腔调」逐角色档案抽取（性格标签 / 口头禅 / 语域）→ 台词风格向量两两对比，超阈值报警
节奏拖沓信息重复；无效对话轮次过多；过渡场景冗长对话轮次统计 + 新信息占比检测（单轮是否推进剧情 / 人物 / 信息）

2.2 使用场景与角色

编剧

初稿写完，面对 60 页剧本不知道从哪改。需要：问题清单 + 定位 + 建议，按严重度排序，一次改一批。

导演

排练前快速过一遍剧本，找「会当场崩掉」的硬伤。需要：高优先级问题摘要 + 张力曲线判断全场节奏。

副导演（ASM）

管理多个修改版本，跟踪修改有没有生效。需要：版本对比 + 分数变化，向团队交代改动依据。

演员（可选扩展）

拿到角色档案卡，理解人物动机与语气。需要：人物档案页作为读本参考。

2.3 目标与非目标

目标（做）

  • 30 分钟内产出一份四维诊断报告，覆盖结构 / 台词 / 人物 / 逻辑
  • 每个问题定位到具体场景、台词与行号，可一键跳转原文
  • 每条诊断给出「问题证据 + 修改建议」，不只说「不好」
  • 支持多版本对比，用分数变化证明修改有效

非目标（明确不做）

  • 不替编剧写剧本——只诊断与建议，创作权在人
  • 不做语音 / 舞台调度 / 排期——那是排期与排练记录方向的范围
  • 不评判艺术价值与审美高低——只做可复现的技术性诊断
03

技术架构

TECHNICAL ARCHITECTURE

五层架构：可复算的用规则和统计做，需要语义理解的交给 LLM 做结构化输出——两者交叉校验，避免「大模型说什么就是什么」。

3.1 技术选型

层级选型选择理由
前端React + Vite + CodeMirror 6编辑器体验接近专业写作工具；组件生态成熟，迭代快
可视化ECharts张力曲线、雷达图、热力图开箱即用，答辩演示效果好
后端FastAPI（Python）异步支持长任务；自动生成 API 文档；与 LLM SDK 同语言、好调试
模型层LLM API（JSON Schema 结构化输出）让分析结果可定位、可复算、可进数据库，而非一段自由文本
存储SQLite单机部署零成本，答辩演示不依赖外部服务
部署本机 Docker / 单进程演示环境简单可控，避免答辩时环境翻车

说明：LLM 只承担「需要语义理解」的子任务（自然度判断、因果校验、档案抽取）；可枚举的检查（人称一致、伏笔匹配、句长统计）全部由本地规则与统计完成——这是本项目区别于「套壳大模型」的关键论证点。

04

数据流程

DATA FLOW

一次完整的诊断是「输入 → 结构化 → 并行分析 → 聚合 → 报告 → 反馈闭环」六步流水线，其中分析环节四个子任务并行执行，长任务通过 WebSocket 实时回报进度。

4.1 评分模型（口径）

维度权重评分依据（示例口径）
结构30%三幕完整性、节拍推进、高潮位置、伏笔—回收覆盖率
台词30%自然度均分（锚定具体句）、口语化程度、信息密度、轮次健康度
人物20%档案一致性得分、台词风格漂移次数、动机清晰度
逻辑20%因果链断裂数、时间线矛盾数、人称/细节一致性

口径说明：以上权重为方案设计值，答辩前用剧社真实剧本校准一次；问题分级「严重（阻断排练）/ 中等（影响观感）/ 轻微（打磨）」。

05

核心功能模块

CORE MODULES
M1 · 结构分析
三幕划分、节拍表、高潮定位、伏笔—回收清单；输出张力曲线与结构评分
M2 · 台词自然度
逐句自然度评分（0–100），检测书面语过重 / 中二宣言 / 独白式 / 信息空转，附降档改写示例
M3 · 人物一致性
逐角色档案卡（性格标签 / 口头禅 / 语域），检测风格漂移与反应矛盾，输出警告列表
M4 · 逻辑检查
因果链校验、伏笔回收匹配、时间 / 人称 / 细节矛盾；规则引擎先行，LLM 补充语义级矛盾
M5 · 版本对比
同一剧本多版本并存，修改前后四维分数对比，采纳建议自动标记「已处理」
M6 · 幽默分析
幽默感 × 冒犯度 × 含蓄度三维检测：有笑点、不冒犯他人、有深度需观众自己会心一笑
M7 · 叙事节奏
节奏曲线（全局张力起伏）、笑点 × 主线排列（笑点不泄主线的气）、双线并行切换（A/B 线怎么切、何时汇）

5.1 M2 台词自然度 · 中二度检测标准（详细设计）

「中二」不是感觉，而是可计算的信号组合：词汇层 + 句法层 + 语义层三层并行检测，结果乘角色 × 场景校准系数，输出 0–100 中二度，并给出「定位 + 信号证据 + 降档建议」。

① 检测标准总表

层检测信号判据 / 阈值（设计值）实现方式
词汇层
权重 40%		中二词表命中密度单句命中 ≥2 个，或每百字 ≥3 个 → 报警规则引擎（词表 + 分词统计，词表可配置）
绝对化 / 全称词密度永远 / 绝不 / 一切 / 必须 / 一定 单场密度 > 正常剧本基线 2 倍规则引擎
强情绪标点密度感叹号占该句标点比 >30%；或连续 ≥3 句感叹号结尾规则引擎
抽象名词占比抽象名词 / 总名词 > 0.5（中二宣言显著偏高）词性标注（jieba / THULAC）
句法层
权重 25%		宣言式句式模板命中正则命中模板库（见 §⑥），每条命中计 1 分规则引擎（模板库可配置）
超长哲理句单句 >40 字且非问句（日常对话罕见）规则引擎
连续独白单一角色连续 ≥3 轮、或单段 ≥80 字无打断 → 演讲腔轮次统计
语义层
权重 35%		情绪反应比例失调事件强度 vs 反应强度评分差 >2 档（0–5 档），如「踩了下鞋」→「你必将付出代价！」LLM 结构化输出（双维度打分）
信息密度过低（空转宣言）单句去修饰后零新信息——不推进剧情 / 人物 / 关系LLM 判定
语域失配日常场景出现史诗语域（史诗词 / 古风词）LLM 场景标签 + 语域检测
重复意象同一角色同义中二意象复用 ≥3 次LLM + 统计
情境校准角色 × 场景调节反派登场 / 高潮场景容忍系数 ×0.6；日常场景从严 ×1.3；中二设定角色降权或豁免校准系数（复用 M3 人物档案的角色定位标签）

词表、句式模板、阈值均为可配置项；答辩前用剧社真实剧本做一次校准。

② 评分模型与分级

③ 情境校准（减少误报的关键）

反派 BOSS 说中二台词是合理的，日常场景的普通人说就是问题——因此最终分数必须乘校准系数，否则系统会天天误报。这也是答辩亮点：检测不是无脑判词，而是「情境感知」的。角色定位标签（反派 / 主角 / 中二设定角色）直接复用 M3 人物档案模块的输出。

④ 降档策略（输出端 · 每条建议 = 定位 + 证据 + 改写方向）

策略做法示例（降档）
大词换小词命运 / 宿命 → 具体事件指称「这就是我的命运！」→「到这儿，走不下去了。」
宣言换动作抽象宣告 → 可见行为或细节「我即是毁灭！」→「我烧了那封信。」

语域回归史诗词 → 口语词（对照词表）「吾之觉悟，天地可鉴」→「我想好了，就这么干。」

⑦ 验证指标（目标值 = 验收标准）

指标目标值度量方式
中二句召回率≥ 75%与 3 位社员人工标注的中二句集合对比
日常场景误报率≤ 10%校准系数生效后，日常场景被误判为中二的台词占比

口径声明：以上为方案设定的验收目标值，非已实测数据；答辩前用真实剧本完成采集后替换。

⑧ 词表校准计划（把误报率压到 ≤10%）

  1. 语料与标注：取 3 部剧社真实剧本，3 位社员独立标注「明显中二」句；标注一致性 Kappa ≥ 0.6 才进入迭代
  2. 跑基线：规则引擎对标注集出分，计算总体召回率与误报率（按场景分层统计）
  3. 词表迭代：删除在正常语境高误报的词（如「觉醒」在励志戏属正常 → 加入场景豁免表），补充漏报词，调整阈值
  4. 再验证：重跑标注集，目标 = 召回 ≥75% 且日常场景误报 ≤10%
  5. 固化配置：校准后的词表 / 阈值存为 v1.json；答辩展示「校准前后对比表」作为迭代证据

5.2 M2 台词自然度 · 幽默分析（幽默感 × 冒犯度 × 含蓄度）

好的玩笑要同时满足三条：有幽默感、不冒犯他人、有深度（不直白，让观众自己会心一笑）。幽默分析把这三条拆成可检测的维度；其中冒犯度是红线，高风险优先处理。

① 检测维度总表

维度检测信号判据 / 阈值（设计值）实现方式
幽默感笑点存在性双关 / 谐音、反差、夸张、自嘲、前文 callback 任一命中 → 有笑点（0–100）LLM 判断 + 谐音词表辅助
笑点类型标注输出类型标签（谐音 / 反讽 / 自嘲 / callback），供深度判断复用LLM
冒犯度
红线维度		群体标签命中性别 / 地域 / 民族 / 职业 / 疾病 / 外貌 / 年龄 贬损词 → 高风险规则词表（可配置）+ LLM 语境复核
贬损对象识别对象 = 群体 → 直接高风险；= 在场角色 → 结合角色关系；= 第三方 → 中风险LLM 对象识别
敏感边界灾难 / 歧视 / 性 / 暴力玩笑 → 红灯必处理规则词表 + LLM
关系不对等单向嘲讽且对象处于低位（长辈 / 新人 / 被排挤者）→ 风险上调LLM 结合 M3 人物档案
含蓄度
深度维度		笑点直白度包袱被解释（「也就是说 / 你懂的」）、谐音直给 → 直白；反讽 / 双关 / callback → 含蓄解释标记词规则 + LLM
深度类型直白梗（0–40）/ 适中（40–70）/ 需思考（70–100），附「观众是否要推理」判定LLM
情境校准角色关系 × 场景朋友互损 ×0.5（容忍）；陌生人 / 严肃场景 ×1.5；有观众在场 ×1.2校准系数（复用 M3 人物档案）

关键设计：同一句「你这头猪」，朋友互损与陌生人辱骂完全不同——所以幽默分析不能纯规则，必须输入角色关系、场景氛围与前文 callback，由 LLM 结合上下文判断；规则只承担群体标签这类可枚举检查。

口径声明：以上为方案设定的验收目标值，非已实测数据；答辩前用真实剧本完成采集后替换。

5.3 M7 叙事节奏 · 节奏曲线 / 笑点×主线排列 / 双线并行切换

观众「觉得闷、觉得乱」往往不是单点台词的问题，而是排列问题。本模块把节奏拆成三块：节奏曲线（全局张力起伏）、笑点 × 主线排列（笑点不能泄主线的气）、双线并行切换（A/B 线怎么切、何时汇）。数据来源全部复用前置模块：张力值来自 M1、笑点定位与空转判定来自 M2/5.2、场景信息密度来自 5.1 语义层。

① 节奏曲线（全局排列）

检测信号判据 / 阈值（设计值）实现方式
张力分布形态前 1/3 出现全局峰值 → 高潮前置；后 1/3 无峰值 → 后劲不足规则（场景张力统计，复用 M1 输出）
张力方差全程张力值方差低于阈值 → 「一条直线」平淡风险规则（标准差）
连续高张力段≥3 场连续高强度 → 观众疲劳规则
平静段长度≥4 场无事件推进 → 拖沓规则（复用 5.1 信息密度）

② 笑点 × 主线排列

检测信号判据 / 阈值（设计值）实现方式
笑点密度分布前半 / 后半笑点密度差 >2 倍 → 前密后疏、后劲不足统计（复用 5.2 笑点定位）
笑点—高潮冲突高潮前 1 场内插入笑点 → 泄气风险（dramatic deflation）LLM（高潮定位 × 笑点定位对照）
空转笑点占比不推进信息 / 关系的笑点占比 >40% → 主线被稀释LLM（复用 5.2 空转判定）
连笑间隔连续 ≥4 场无笑点 → 流失风险；单场 ≥3 个笑点 → 廉价堆叠统计

③ 双线并行切换

检测信号判据 / 阈值（设计值）实现方式
线识别角色—场景共现矩阵聚类 → 场景归属 A 线 / B 线（如 现实线 vs 回忆线）规则（聚类，可复算）
切换频率平均每 <2 场切换 → 过频（观众跟不上）；单线连续 ≥4 场 → 另一线被遗忘统计
切换动机切换是否发生在悬念点（cliffhanger）切入；无动机切换 → 生硬LLM
线间关联两线是否存在主题 / 因果连接；完全无关 → 观众困惑「为何双线」LLM
结尾交汇两线是否在末段交汇（convergence）；未交汇 → 结构残缺LLM + 规则

④ 输出与建议

节奏总览图：张力曲线 + 笑点散点 + 主线推进标记（答辩用「全场心电图」），问题清单定位到具体场景：

  • 节奏：高潮前移 / 后移；平静段插入小冲突
  • 笑点：从高潮区移走；分散堆叠的笑点；把空转笑点改成推进信息
  • 双线：切换点移到悬念处；单线超长强制切回；结尾补交汇

⑤ 验证指标（目标值 = 验收标准）

指标目标值度量方式
节奏问题召回率≥ 70%与导演人工标注的节奏问题对比
切换生硬点检出率≥ 75%与人工标注的 A/B 切换点对比
建议采纳率≥ 50%导演采纳 / 部分采纳的建议条数占比
